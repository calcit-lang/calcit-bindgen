# Render native WASI async WIT / 生成原生 WASI async WIT

## 中文

- 让 Component Interface IR v3 的 `async` invocation 生成 WASI 0.3 原生 `async func`，同时保持 `sync` invocation 生成普通 `func`。
- 覆盖 async import、async export 与同步 export，并使用 WIT parser 验证完整生成结果。
- 将测试工具链升级到 Wasmtime 47.0.4，并启用 `component-model-async`；该版本满足 Wasmtime 46+ 的验收目标，同时兼容当前 Rust 1.94 工具链。
- 按照 Wasmtime 47 的 API 迁移测试，移除已经无效果的 `TypedFunc::post_return` 调用。
- 明确保留 fail-closed 边界：生成 WIT 不代表 core module 已具备 async Canonical ABI；缺少 builtin wiring 时 packaging 仍会在写入产物前失败。

## English

- Render native WASI 0.3 `async func` declarations for Component Interface IR v3 `async` invocations while keeping ordinary `func` declarations for `sync` invocations.
- Cover async imports, async exports, and sync exports, then parse the complete generated document with the WIT parser.
- Upgrade the test toolchain to Wasmtime 47.0.4 with `component-model-async`; this satisfies the Wasmtime 46+ acceptance target while remaining compatible with the current Rust 1.94 toolchain.
- Migrate tests to the Wasmtime 47 API by removing `TypedFunc::post_return` calls, which no longer have any effect.
- Preserve the fail-closed boundary explicitly: rendering WIT does not claim that the core module implements the async Canonical ABI, and packaging still fails before writing artifacts when builtin wiring is absent.

## Verification / 验证

- `cargo fmt --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test`
- `cargo package --allow-dirty`
